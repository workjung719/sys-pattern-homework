# Домашнее задание к занятию "`Резервное копирование баз данных`" - `Лазебный Кирилл`

---

### Задание 1. Резервное копирование

1.1 Восстановить за прошлый день: Делаем обычный полный бэкап (Full Backup). Настраиваем делать его раз в сутки ночью во время минимальной нагрузки.

1.2 Восстановить за час до поломки: Одного полного бэкапа мало, нужны еще логи изменений (инкрементный бэкап). Можно использовать механизм PITR (Point-in-Time Recovery). С полного последнего бэкапа накатываешь логи транкззаций вплоть до нужной минуты перед сбоем.

1.3* Моментальное переключение: Да, такой кес возможен. Поднимается репликация (основная база — Мастер, запасная — Реплика). Если Мастер падает, Реплика за секунды становится главным сервером и простоя почти нет.


---

### Задание 2. PostgreSQL

2.1 Для резервного копирования одной конкретной базы используется утилита pg_dump. Удобнее всего делать бэкап в кастомном формате (-F c), так как он сжат и отлично подходит для pg_restore

Создание бекапа:
pg_dump -U username -h hostname -F c -d dbname -f /path/to/backup_file.dump

Восстановление из бэкапа:
pg_restore -U username -h hostname -d dbname -1 /path/to/backup_file.dump

2.1* В Linux пишется небольшой bash-скрипт, в котором прописана команда pg_dump с добавлением текущей даты в имя файла. Этот скрипт добавляется в планировщик задач cron (например, 0 2 * * * /path/to/script.sh — запуск каждый день в 2 ночи).

### Задание 3. MySQL

3.1 Согласно официальной документации MySQL, для "настоящего" инкрементного копирования  используется коммерческая утилита MySQL Enterprise Backup.

Создание бекапа: 
mysqlbackup --defaults-file=/etc/my.cnf \
  --incremental \
  --incremental-base=history:last_backup \
  --backup-dir=/path/to/inc_backup \
  backup

3.1* Реплики будет давать преимущество по сравнению с обычным резервным копированием в следующих случаях:

Скорость восстановления (RTO ~ 0): Если сервер падает, разворачивание базы из файла бэкапа в несколько терабайт может занять часы. На реплику же трафик переключается за секунды.

Балансировка нагрузки на чтение: Файл бэкапа просто лежит на диске мертвым грузом, а реплика живая база. На неё можно направить все запросы типа SELECT, разгрузив тем самым основной сервер только для записей (INSERT, UPDATE).

Аналитика без тормозов: На реплике можно запускать тяжелые аналитические выгрузки, не боясь повесить основной продакшен-сервер.
